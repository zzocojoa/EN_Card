# 작은 압축 블록 구현·로컬 비교

2026-10-03 / `codex/ai-card-automation` / 기반 `ad875e8`

**N3 구현·로컬 비교는 완료했으나 기본 경로에 채택하지 않는다.** 전체 생성의 반복 평균은 글자별38.080ms,4글자37.994ms,8글자38.801ms였다.4글자의 감소는0.086ms(0.23%)이며 같은 입력30쌍 중15쌍에서만 반복 평균이 짧았다. 첫 준비 시간도 늘어 일관된 개선 근거가 부족하다. 기존 ATG1/JSON/fetch를 유지한다.

N3은 기존 64슬롯 페이지 안에서 인접한4/8글자를 하나의 zlib 스트림으로 묶는 실험이다. N1 RPC와 N2 ATC 바이너리화를 섞지 않고 기존 JSON/fetch·호출당6페이지·800/720·scalar·JS CRC·Z_RLE를 유지한다. 운영 소스·기본 배포 설정은 변경하지 않았다. 새 원격 배포·계정 조회·AI·카카오 호출은 없다.

## 구현과 보호 조건

- [atlas-blocks.ts](../experiments/automation-png/atlas-blocks.ts): ATG2 해독기. 요청한 글자의 블록을 페이지 해독 호출당 한 번만 해제하며 호출이 끝나면 캐시를 버린다.
- [atlas-block-build.ts](../experiments/automation-png/atlas-block-build.ts), [prepare-block-pages.ts](../experiments/automation-png/prepare-block-pages.ts): 전체 글자 오프라인 변환·대조. 운영 Worker에는 압축용 빌더를 넣지 않는다.
- `atlas-block-runtime.ts`, `atlas-block-worker.ts`, `atlas-block-probe.ts`: 명시한 `BLOCK_SIZE=4/8`과 일치하는 페이지를 읽는 비공개 렌더러·Secret 인증 입구.
- [atlas-chunks.ts](../experiments/automation-png/atlas-chunks.ts), [atlas-pipeline.ts](../experiments/automation-png/atlas-pipeline.ts): 선택적인 페이지 해독기 연결만 추가했다. 생략하면 기존 ATG1이다. ATC1/ATB1·그리기·PNG 검증은 동일하다.
- [block-inputs.ts](../experiments/automation-png/block-inputs.ts), [research-blocks-workerd.mjs](../experiments/automation-png/research-blocks-workerd.mjs): 실제 페이지·같은 PNG·실제 로컬 바인딩을 사용한 비교. `atlas-block-micro.ts`는 배포 설정이 없는 로컬 전용 페이지 해독 시험 입구다.

ATG2는24바이트 헤더,64개×32바이트 글자 레코드,블록당16바이트 위치표,압축 데이터를 저장한다. 모든 다중 바이트 필드는 big endian이다. 글자 슬롯에서 블록 번호를 계산하고 레코드의 오프셋은 해제된 블록 안의 위치다. 소수 폭은 float64, 위치는 int16을 유지한다. ATG1/ATG2와4/8블록 혼용을 거부한다.

페이지4MiB, 글자200×200, 블록별 해제 상한4글자160,000B/8글자320,000B를 적용한다. 압축 위치·길이·선택 글자 범위·형식·예약 필드·누락·중복을 검사하고, 읽은 블록의 모든 알파0~31을 검사한다. 선택하지 않은 이웃 픽셀도 해제·검사 비용에 포함된다. 요청하지 않은 블록은 해제하지 않는다. 상한은 `inflateSync`의 `maxOutputLength`에도 전달하고 선언된 크기와 실제 출력이 같아야 한다. 이 옵션은 동기 편의 함수의 출력 크기를 제한한다. [Node.js 공식 문서](https://nodejs.org/api/zlib.html#class-options).

선언된 해제 크기를 넘기는 압축 데이터가 실제 로컬 workerd에서도 거부되는 것을 확인했다. 새 `rejectGarbageAfterEnd` 같은 옵션이나 유료 런타임 의존성은 도입하지 않았다.

## 전체 글자 보존과 해제 작업량

원본12,580페이지의 글자780,504개(글자·굵기·크기·해상도 조합)를 각 후보로 변환했다. 후보별 모든 글자의 메타데이터와 픽셀을 원본과 대조했다. 총25,160개의 변환 페이지를 검증했으며 예제에서 쓰는 글자만 추린 것이 아니다. 각 후보는 라이선스2개를 포함한 별도12,582파일 디렉터리다. 두 후보를 한 배포의 자산 디렉터리에 합치지 않는다. [전체 변환 결과·트리 해시](evidence/AI_PNG_BLOCK_BUILD_2026-10-03.json).

한글 실물 페이지의 단일/밀집/분산 요청도 별도로 비교한다. 밀집은 슬롯0~7, 분산은0/8/16/24/32/40/48/56이다. 밀집8글자는 inflate8→2→1회, 분산8글자는8→8→8회다. 블록 방식의 이점이 글자 배치에 의존함을 보여주는 고정 사례이며 모든 한국어 문장의 분포를 대표하지 않는다.

## 측정 방식

세 라운드에서 형식 순서를 순환시켜 같은 입력의 각 형식이 첫째/둘째/셋째 위치를 한 번씩 차지하게 한다. 가운데 라운드는 입력 순서도 반전한다. 준비/전체 경로는 예제10종, 페이지 해독은 분포3종×해상도2종이다. 새 인스턴스마다 첫1회·안정화2회·반복10회다.

- 준비: 한 카드의 준비 요청 전체를 순서대로 호출하고 실제 로컬 Static Assets를 읽는다. 여러 Worker 호출과 각각의 호스트 경계를 포함한다.
- 전체: 인증 입구에서 실제 fetch Service Binding·자산 읽기·조립·전체 PNG 응답 읽기까지다.
- 페이지 해독: 준비한 한글 페이지를 실제 workerd HTTP 요청 본문으로 보내고 글자 메타데이터·픽셀 응답을 읽는다. 자산 조회는 없으며 본문 읽기·해독·ATC1 인코딩·전달을 포함한다.

모든 값은 호스트 경과 시간이며 순수 해제 CPU나 Cloudflare CPU가 아니다. 바이트 대조는 타이머 밖이다. `mf.ready`와 바인딩 획득은 별도 `setup_wall_ms`로 남기므로 첫 요청이 전체 플랫폼 cold start는 아니다. 프로파일러는 연결하지 않는다. 세 모집단은 경계가 다르므로 합산하지 않는다. 조립 입력 ATC1/ATB1 바이트가 동일함을 확인하며 조립만 따로 중복 측정하지 않는다.

## 검증·리뷰와 남은 단계

- 관련 Vitest5파일61개 통과. 새 블록 검사8개와 기존53개이며, 기존 실제 폰트·동적 한영 PNG 검사에 두 블록 형식의 일치를 추가했다. 전체 제품 Vitest/E2E를 새로 실행한 것은 아니다.
- 전체 글자 변환 대조와 별개로 실제 로컬 workerd에서 **PNG1,200개·준비 프레임8,640개·페이지 해독 응답720개**가 기준과 같았다. 측정234개 새 인스턴스와 별도 smoke21개다. PNG는 smoke30+전체1,170, 준비 프레임은 smoke216+측정8,424, 페이지 응답은 smoke18+측정702다. 입력 준비 단계의 Node PNG와 전체 경로 내부 프레임은 중복 집계하지 않았다. 사전 PNG 응답으로 계산을 대체하지 않았다.
- 실제 로컬 workerd 거부51건을 통과했다. 인증·메서드·고정 경로·조립 상한·잘린 묶음·압축 checksum·선언된 해제 크기 초과를 포함한다.
- 타입·Vite·제품 두 Worker dry-run, 무료 구성 검사, 두 블록 후보의 렌더러/입구 네 가지 dry-run을 통과했다. 시험 렌더러 gzip1,569.08KiB·입구1,566.15KiB다. 기본 구성 검사는 계정 청구·원격 CPU 적합성의 증명이 아니다.
- 요청한 `review`의 테스트·성능·보안·유지보수 전문 검토와 독립 적대적 검토에서 구체적인 미수정 결함을 찾지 못했다. 테스트 전문 검토는 테스트 원문을 읽고 적대적 검토는 테스트·fixture 요약만 읽었다. 같은 모델의 검토이며 별도 모델/Claude/CLI 통과로 주장하지 않는다.

원격 PNG 누적88개, 기존 CPU 초과·로그 누락과 전체 AI 자동화2~5단계 미완료 상태는 유지한다. 계정 Free 여부·공유 쿼터·원격 CPU·최대 메모리 실측·실제 AI/카카오 연동은 이번 단계에서 새로 확인하지 않았다. 기존 임시 Worker·Secret은 정리된 상태이며 새 유료 자원·의존성도 추가하지 않았다.

다음 미완료 후보는 **N4: 글자 그리기만 작은 Wasm SIMD 함수로 비교**다. 첫 실행의 모듈 준비·입출력 복사 비용까지 포함해야 한다. 원격 CPU 적합성과 로그 확보율이 해결되기 전에는 무인 자동화를 운영 활성화하지 않는다.

## 재현

`.automation-png` 원본 자산이 없으면 [최적화 재현 명령](AI_CARD_AUTOMATION_OPTIMIZATION.md#재현-명령)의 전체 atlas→common→optimized-build→자산 복사→optimized 기준PNG 생성 순서를 먼저 실행한다. 이후 저장소 루트에서:

```powershell
npm test -- tests/automation-blocks.test.ts tests/automation-binary.test.ts tests/automation-rpc.test.ts tests/automation-atlas.test.ts tests/automation-optimized.test.ts
node scripts/prepare-automation-blocks.mjs
node experiments/automation-png/research-blocks-workerd.mjs --smoke
node experiments/automation-png/research-blocks-workerd.mjs
npm run build
npm run check:free
npx wrangler deploy --config experiments/automation-png/wrangler.atlas-block4.jsonc --dry-run
npx wrangler deploy --config experiments/automation-png/wrangler.atlas-block4-probe.jsonc --dry-run
npx wrangler deploy --config experiments/automation-png/wrangler.atlas-block8.jsonc --dry-run
npx wrangler deploy --config experiments/automation-png/wrangler.atlas-block8-probe.jsonc --dry-run
```

원격 배포 명령이 아니며 실제 Secret이 필요하지 않다. 측정 중 테스트·빌드·다른 CPU 부하를 실행하지 않는다. 도구는 `finally`로 인스턴스를 정리한다. 같은 명령은 해당 날짜의 결과 파일을 다시 작성하므로 이전 결과를 보존하려면 먼저 복사한다. 과거 원격 원장은 변경하지 않는다.

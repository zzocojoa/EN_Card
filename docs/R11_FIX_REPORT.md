# R11 연결 해제 이력의 복구 편입 수정

기준은 codex/development의 03797ad4fb055129dd8868418f30af79c91d18ee다. 과거 연결 해제 취소 → 예약 수정으로 같은 고정 이미지 발송 → 일시정지 → 0009/0010 업그레이드에서 이미 보낸 옛 카드가 확정 미발송으로 제시되는 P2 결함을 수정했다.

## 재현과 수정

새 회귀를 수정 전 제품 코드에 실행해 16:19:35 KST에 **1개 실패**를 확인했다. expected items=[]·pending_count=0과 달리 available=true인 옛 연결 해제 카드 한 장이 나타났다. 이 실패는 실제 제품 함수와 격리 Miniflare DB를 사용한 결함 재현이며 카카오 실제 수신 시험은 아니다.

- 이미 적용된 0001~0010을 보존하고 0011_delivery_cancellation_reason.sql을 추가했다. 알려진 과거 취소 원인을 분류하고 일시정지가 아닌 **미결정** 복구 관계만 제거한다.
- deliveries.cancellation_reason은 paused/cancelled/schedule_changed/disconnected 또는 NULL이다. 기존 state·error·payload·claim·실제 시도·예산을 변경하지 않고 새 필드를 채운다. 모르는 과거 원인은 추측하지 않고 NULL로 남긴다.
- 새 예약 수정·중지·연결 해제·확정 거절 완료 경로는 구조화된 원인을 쓴다. 성공/unknown은 취소 원인을 쓰지 않는다. 복구 기록 트리거는 paused 원인과 부모의 일시정지 상태를 함께 요구하며 화면 오류 문구를 판단에 사용하지 않는다.
- 완료된 reschedule/exclude와 대상 목록·예약은 보존한다. 과거의 명시적 선택을 자동으로 되돌리거나 연결 해제된 카드를 새로 보내지 않는다.

수정 파일은 migrations/0011_delivery_cancellation_reason.sql, src/shared/model.ts, src/worker/{auth,engine,schedules}.ts와 회귀 테스트다. 과거 0008/0010 DB를 재현하는 테스트에만 새 필드 대입을 제거하는 어댑터를 사용한다. SQL 인수와 나머지 과거 동작은 그대로이며 0011 적용 후 이 어댑터는 해제된다. 운영 코드에 옛 스키마 우회는 없고 새 서버 배포 전 0011이 필요하다.

R11은 옛 연결 해제 후보 제거·오래된 선택 요청 거부·재개 가능, delivery의 새 필드 이외 불변·호출/예산/FK 보존을 검사한다. 혼합 DB에서는 진짜 일시정지의 미결정·복구/제외, 잘못 편입됐지만 이미 완료된 결정과 대상 목록·예약, 미분류 이력을 보존한다. 최신 스키마의 연결 해제/수정과 일시정지를 오류 문구 변경으로 구분하는 검사도 추가했다. R8/R10의 거절·성공·unknown에 구조화된 원인 검사를 추가했고, R5의 40/41/45 경계를 0011까지 적용한 DB에서 실행했다.

전체 Chromium은 현재 Windows 환경에서 정상 실행됐다. 보고서에서 언급한 Wrangler uv_interface_addresses 오류는 이번 환경에서 재현되지 않았다. 마지막 일회/매일/요일 5장의 미발송 2장 복구/제외·성공 3장 보존과 누적 45장 부분 처리를 포함한다. 서버 검사는 격리 DB/KV·합성 인증·모의 제공사 응답이며 Chromium은 로컬 Worker·실제 Canvas PNG를 사용한다.

## 운영 상태와 적용 방법

R11 작업 중 운영 읽기 전용 조회에서 0001~0010 이력, 연결 해제 cancelled 이력 **0건**, 해당 미결정 복구 관계 **0건**, 전체 pause_recoveries **0건**, FK 오류 **0건**을 확인했다. 이 조회에는 토큰·세션·키가 포함되지 않았고 DB 변경은 없었다. 이 결과로 다른 DB의 업그레이드 결함을 부정하거나 마이그레이션을 생략하지 않는다.

로컬 수정 종료 시 운영 제품 소스는 이전 9965568이며 0011과 R11 코드는 미적용이었다. 이후 사용자 승인으로 2026-10-01 17:04 KST에 0011과 검증본 6ec4579를 운영에 반영했다. 추가 실제 카카오 메시지·키/토큰/예약 변경은 수행하지 않았다. 이전 실제 이미지·원본·PC 종료 수신·CPU 측정은 당시 기록으로 보존한다. R11의 실제 발송·갱신 CPU는 미측정이다.

운영 적용은 SETUP.md의 백업·쓰기 중단·진행 중 호출 종료 확인 → 미적용 0011 → FK/11개 이력 → 비공개 발송 Worker → 메인 Worker 순서다. 0011 후에는 취소 원인 쓰기를 지원하는 호환 코드로만 복귀한다. 이미 결정된 비일시정지 관계는 OPERATIONS.md의 조회와 원래 메시지·결정·대상 예약 확인을 따른다. 자동 재발송·자동 선택 취소를 하지 않는다.

운영 적용 전 DPAPI 암호화 백업의 왕복 해시와 접근 제한을 확인했다. 15개 테이블의 전후 행 해시를 비교했으며 delivery의 새 열을 제외한 원본 데이터에서 바뀐 테이블은 d1_migrations 하나다. 기존 7개 delivery의 취소 원인은 모두 NULL이고 정리 대상 관계는 0건이었다. 이력 11개·FK 오류 0, 실제 트리거의 paused 원인 조건, 기존 운영자 화면·원본 PNG·접근 제어를 확인했다. 두 Worker는 각각 100% 새 버전이며 매분 Cron 하나와 기존 D1/KV·Secret을 유지한다. 상세 시각·버전과 검증은 [VERIFICATION.md](VERIFICATION.md)를 따른다.

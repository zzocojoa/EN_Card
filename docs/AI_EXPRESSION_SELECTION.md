## 바뀌는 동작

기존에는 최근 50개 표현을 AI에 전달하고 카드 전체를 작성한 다음 모든 카드·영구 표현 기록과 비교했다. 중복의 최종 저장은 막았지만 뜻·예문까지 생성한 호출을 소비했다.

새 작업은 다음 순서로 실행한다.

1. 주제·난이도·템플릿·비교 기본 표현이 같은 미사용 후보를 찾는다. 없으면 기존 무료 제공자에게 표현만 최대 10개 요청한다(`stage=select`). 날짜·수량·발송 시각은 후보 분류에 포함하지 않아 다음 날에도 재사용한다.
2. 최근 50개뿐 아니라 전체 `cards` 및 `automation_expressions`와 대조한다. 후보 목록 내부의 대소문자/앞뒤 공백 중복도 하나로 합친다. 거절된 오래된 표현도 기록해 다음 요청의 제외 목록에 먼저 넣는다. 검사 후 저장하는 후보는 전체 최대 50개다.
3. D1 batch에서 후보의 유일한 `claim_run_id`와 작업의 `selected_expression`을 함께 기록한다. 후보를 읽기만 하고 카드 작성을 호출하지 않는다. 동시에 같은 후보를 요청한 두 작업은 서로 다른 표현을 확보하거나 한쪽이 후보 부족으로 대기한다.
4. 확정된 표현으로 뜻·예문·번역을 작성하고 최종 작성자 반대 제공자의 독립 검토를 받는다. 수정도 같은 표현을 유지하며 다른 표현을 반환하면 `invalid`로 처리한다.
5. 최종 품질 탈락 후 허용된 새 후보 1회로 넘어갈 때 선택 표현을 해제하고 거절 이력을 같은 DB 변경 안에 남긴다. 같은 날짜·종류·설정 버전의 다른 카드도 그 표현을 선택하지 않는다. 다음 회차에는 다시 평가할 수 있다.
6. 이미지 저장 시 기존 영구 표현 기록이 예약을 이어받고 임시 후보를 제거한다. 실패·취소·마감은 임시 예약을 해제한다. 사용한 카드·시도·검토 기록은 지우지 않는다.

예: 최초 후보 10개 중 기존 표현 2개를 제외하고 8개 보관 → 5개를 각각 예약해 작성/검토 → 남은 3개는 동일 조건의 다음 제작에 사용. 후보는 검토 완료 카드가 아니며 직접 발송할 수 없다.

## 비용·시간·안전 경계

- 후보 호출도 카드당 기존 24회 예산에 포함한다. 단계/차수/제공자별 최초 포함 3회, Google 이후 Groq 대체, 품질 수정 최대 2회·새 후보 1회 제한을 유지한다. 후보만 반복돼도 무한 호출하지 않는다. `candidate_empty`는 후보 재확인 대기, `candidate_limit`은 유효 후보 확보 한도 소진이다.
- 한 tick에 AI는 최대 1회다. 후보 조회 직후 같은 tick에서 카드 작성까지 연속 호출하지 않는다. 확보된 후보를 재사용할 때는 별도 후보 호출이나 대기 tick이 없다.
- 처음 5장을 오류 없이 만들면 후보 1회 + 작성 5회 + 독립 검토 5회 = **11회**다. 기존 오류 없는 10회보다 최초 조회 1회가 추가된다. 이 비용을 여러 카드/다음 날에 나누고 중복 카드 전체 재작성을 줄이는 방식이며, 실제 총 호출 감소를 보장하지 않는다.
- 새 방식의 최종 품질 대체는 후보 보충까지 고려해 최소 3회 호출 여유와 마감까지 7분 초과를 요구한다. 기존 작업은 원래 2회/6분 조건을 유지한다. 진행 중 작업의 마감·시도 예산·수정 차수를 초기화하지 않는다.
- 수동 카드가 뒤늦게 추가되는 경우를 작성 전후·PNG 전 및 최종 저장에서 다시 확인한다. 네트워크 호출 중 추가된 중복은 생성 전 완전히 차단할 수 없지만 검토/이미지/발송 전에 제외한다.
- 표현 비교는 기존 `trim().toLowerCase()` 계약을 유지한다. 의미가 비슷한 다른 표현, 내부 공백·구두점·유니코드 변형까지 같은 표현으로 판단하는 기능은 포함하지 않는다.
- 제공자 응답 실패, 기존 순차 대기, 90분 전 제작 시작은 이번 변경 대상이 아니다. 현재 60분 준비/55분 제작창·PNG 2분 대기를 유지한다.
- 새 외부 서비스·유료 API·한도 상향은 없다. 계정 무료 자격/공유 사용량과 원격 CPU는 로컬 검사와 별도로 확인한다.

## 스키마와 호환성

`0023_automation_expression_selection.sql`은 실행에 `expression_selection`과 `selected_expression`, 임시 후보와 회차별 거절 테이블, 조회 인덱스 및 예약 해제 트리거를 추가한다. 기존 실행은 mode 0을 유지하고 새 정규/시험 등록 코드만 mode 1로 생성한다. 기존 카드·자식 참조·발송 결과를 재작성하지 않는다.

이전 실행의 회귀 테스트는 `legacyAutomationHarness`로 mode 0 작업을 만들며, 변경된 SQL의 모드 리터럴만 역사적 입력값 0으로 바꾼다. claim·검토·발송 가드는 실제 SQL로 실행한다. 새 기본 등록/선정 흐름은 이 도우미를 사용하지 않는 `automation-expression-selection.test.ts`에서 별도로 검증한다.

# EN_Card 중대 결함 조사·개선 계획

작성일: 2026-10-07 / 기준: `master@33774a0`

상태: 계획 문서 저장 완료. 이 문서는 조사·수정·검증 완료 기록이 아니다.

## 1. 목표와 완료 범위

병합된 `master@33774a0`을 기준으로 운영 중 중복 발송, 인증정보 노출, 데이터 손실, 지속적인 자동화 중단을 일으킬 수 있는 결함을 조사한다. **확인된 결함 수정 → 재현 테스트 통과 → 리뷰 → PR 생성**까지 수행한다. 운영 배포·실제 추가 발송·병합은 후속 단계로 둔다.

- 작업 시작 시 원격 기본 브랜치와 변경 사항을 확인하고 `codex/critical-defect-audit` 브랜치를 생성한다. 기준이 달라졌으면 차이를 조사 기록에 포함한다.
- EN_Card 전체 운영 경로와 하루단어의 카드 인증·프록시·AI 릴레이 연결 부분을 포함한다.
- 하루단어 일반 학습 기능, 디자인 개선, 기능 확장, 포괄적인 리팩토링은 제외한다.
- 조사 중 발견한 위험을 이미 확인된 결함처럼 표현하지 않는다.

## 2. 조사 순서와 검증할 규칙

| 순서 | 영역 | 반드시 검증할 규칙 |
| --- | --- | --- |
| 1 | 예약·발송 | 동시 Cron이 같은 발송을 중복 실행하지 않는다. 취소·버전 변경을 호출 전에 확인한다. 접수 여부가 불명확하면 자동 재발송하지 않는다. |
| 2 | 인증·접근 제어 | 소유자 외 접근과 위조된 연결 요청을 거부한다. OAuth 응답 재사용을 막고 토큰·키가 응답·로그·공개 파일로 노출되지 않는다. |
| 3 | AI 제작·검토 | 현재 내용과 일치하는 독립 검토를 통과한 카드만 예약한다. 수정·중복 재생성·새 후보·제공자 대체가 호출 예산과 마감을 우회하지 않는다. |
| 4 | 데이터·이미지 | D1/KV 부분 실패에도 이미지 참조·용량 집계가 보존된다. 예약·미확정 발송이 참조하는 이미지를 삭제하지 않는다. |
| 5 | 중단·재개·시간 | 만료된 잠금은 안전하게 회수한다. 토큰 갱신·재연결·시험 종료가 사용자 설정을 덮어쓰지 않는다. 날짜 경계와 종료일을 정확히 처리한다. |
| 6 | 한도·운영 구성 | 동시 요청에도 예산 상한을 지킨다. 개발용 인증·모의 성공이 운영으로 유입되지 않는다. 실제 배포 버전과 검증 소스를 구분한다. |

화면도 조사에 포함하되, 실패를 성공으로 표시하거나 위험한 재시도를 유도하는 동작에 집중한다. 정상적인 품질 탈락으로 수량이 줄어드는 현상 자체는 중대 결함으로 분류하지 않는다.

## 3. 재현과 수정 방식

- 먼저 기존 테스트 결과를 확보하고, 기존 실패와 이번 변경으로 생긴 실패를 구분한다.
- 기존 Miniflare 기반의 격리된 D1/KV와 모의 AI·카카오 어댑터를 사용한다. 실제 SQL과 조건부 갱신을 검증하며, 핵심 저장 동작 전체를 모의 성공으로 대체하지 않는다.
- 동시성 테스트는 임의 대기시간에 의존하지 않고 실행 순서를 제어한다. 외부 호출 직전·직후, 저장 성공·실패 경계에서 중단과 응답 유실을 재현한다.
- 재현 가능한 결함은 **수정 전 실패하는 테스트를 먼저 확보**하고 최소 범위로 수정한다. 인접한 상태 전이와 복구 경로도 함께 검증한다.
- P0는 인증정보 탈취·소유권 우회·복구 불가능한 데이터 손실, P1은 중복·취소 후 발송·검토 우회·지속적인 예약 중단·예산 우회로 분류한다. 재현 조건과 피해 범위로 최종 심각도를 판단한다.
- 확인된 P0/P1과 수정에 직접 필요한 원인을 처리한다. 그 외 개선은 별도 목록으로 남긴다.

공개 API·응답 형식·상태 타입·DB 스키마는 기본적으로 유지한다. 결함 해결에 변경이 꼭 필요하면 호환성 및 기존 데이터 보존 테스트를 추가하고, 마이그레이션은 격리된 로컬 환경에서만 검증한다.

하루단어 수정이 필요하면 진행 중인 PR #33과 분리한 브랜치·PR로 처리한다. 생성 파일은 EN_Card의 정식 exporter를 통해 갱신한다.

## 4. 테스트와 판정 기준

필수 장애 시나리오:

- 같은 회차의 동시 claim, 잠금 만료 후 늦게 도착한 응답, 카카오 접수 후 DB 기록 실패.
- 취소·일시정지·재연결과 발송의 경합, 미해결 `unknown`이 있는 상태의 재개.
- AI 503·인증 실패·쿼터 초과·잘못된 JSON·과대 응답·마감 후 응답.
- 검토 후 내용 변경, 다른 후보의 검토 결과 혼용, 중복 및 새 후보 전환 중 중단.
- KV 저장 성공 후 D1 실패, 이미지 삭제와 예약 등록의 경합, 예산의 동시 소비.
- KST 자정·월말·윤일·종료일, trial과 daily 구분, 시험 중 사용자가 설정을 변경한 경우.

수정 후 관련 테스트, 전체 `npm test`, `npm run typecheck`, `npm run build`, `npm run check:free`를 실행한다. 화면·연동을 수정한 경우 관련 브라우저·하루단어 통합 검증도 수행한다.

CPU는 로컬 실행시간으로 운영 적합성을 판정하지 않는다. 기존 실측의 버전·대상 경로·관측 공백을 확인하고, 실행 경로 변경으로 원격 재검증이 필요하면 PR에 배포 전 필수 항목으로 남긴다.

## 5. 산출물과 PR 완료 조건

- `docs/CRITICAL_DEFECT_AUDIT.md`: 조사 기준, 영역별 결과, 결함 위치·재현 절차·영향·수정 근거·남은 검증.
- `docs/PROGRESS.md`와 `docs/VERIFICATION.md`: 이번 작업과 실제 실행한 검증 결과.
- 재현 테스트와 최소 수정 코드, 관련 PR 및 저장소 간 의존 관계.

각 조사 항목은 **결함 확인·수정 완료 / 조사 범위에서 미발견 / 미검증**으로 구분한다. 필수 검증이 실패하거나 확인된 P0/P1이 남으면 완료로 선언하지 않고 PR을 Draft로 유지한다.

최종 리뷰는 변경 내용과 관련 상태 전이를 다시 확인한다. 등록 CI가 없는 EN_Card는 로컬 검증 근거를 PR에 명시한다. 결함이 발견되지 않은 영역은 불필요하게 수정하지 않으며, 무결함이나 향후 모든 실행의 성공을 보장하지 않는다.

# PNG 조립 함수 분리·native CRC 로컬 비교

2026-10-03 / `codex/ai-card-automation` / 기반 `ad875e8`

**다음 원격 검증 후보는 글자 그리기 함수 분리와 native CRC의 조합이다.** 같은 마지막 실험에서 첫 조립의 로컬 경과 시간 중앙값은 13.82→12.74ms, 반복 평균은 4.30→4.29ms였다. 첫 실행 후보로 선택할 근거는 있지만 반복 시간 개선이나 Cloudflare CPU 10ms 통과를 입증하지는 않는다.

이번 작업은 로컬 구현·비교다. 원격 생성은 추가하지 않아 누적 PNG는 **88개**이며, 마지막 원격 시험의 CPU 초과·로그39개 누락은 미해결이다. AI 작성·교차 검토·자동 예약·운영 UI인 계획2~5단계도 미완료다. [직전 실제 CPU 진단](AI_CARD_AUTOMATION_DIAGNOSTIC.md)을 보존한다.

## 비교한 구현과 선택

| 후보          | 구현                                                               | 판단                                          |
| ------------- | ------------------------------------------------------------------ | --------------------------------------------- |
| 기존 `scalar` | 배치·문자 처리 안에서 픽셀별 JS 반복                               | 대조군으로 보존                               |
| `extracted`   | 픽셀 반복을 작은 함수로 분리하고 팔레트 곱셈을 글자당 한 번 계산   | 가장 단순한 그리기 후보                       |
| `packed`      | 4픽셀씩 읽어 0인 알파는 보존하고 나머지 색상 인덱스를 한 번에 기록 | 첫 경과 시간이 더 길어 선택하지 않음          |
| `spans`       | 글자별 연속된 불투명 구간을 만들어 `Uint8Array.set`으로 복사       | 임시 할당이 늘고 시간이 더 길어 선택하지 않음 |
| `native`      | `extracted`와 `node:zlib.crc32`를 함께 사용                        | 다음 검증 후보로 선택                         |

`atlas-blit.ts`의 후보들은 요청 안에서만 상태를 보관한다. 투명 픽셀 위의 기존 글자, 겹침, 배열의 byteOffset, 4로 나누어떨어지지 않는 폭을 보존한다. 선택하지 않은 후보도 비교 재현을 위해 실험 폴더에 남겼다.

`atlas.ts`의 명시적 옵션으로만 후보를 고른다. `src/worker/png.ts`에는 신뢰하는 내부 CRC 함수를 받을 인자를 추가했으며, 제품 업로드는 기존1080·JS CRC 기본값을 유지한다. 요청 입력이 검사 함수를 선택할 수 없다. **청크 구조·길이·순서·크기·CRC 일치 검사는 모두 유지**한다. [Node 공식 CRC 문서](https://nodejs.org/api/zlib.html#zlibcrc32data-value)의 바이트 배열 입력을 사용하며, 이 런타임의 동작은 로컬 workerd에서도 확인했다.

`atlas-blit-worker.ts`와 `wrangler.atlas-blit.jsonc`는 compile-time `BLIT_MODE=native`로 선택한 비공개 시험 구성이다. 기존800/720 고정 예제 경로를 사용하며 D1·KV·Cron·AI·카카오 바인딩은 없다. 운영 배포나 제품 이미지 규격 변경은 하지 않았다.

## 측정 방법

`research-blit-workerd.mjs`가 실제 검증된 글자 묶음과 기준 PNG를 준비한 후 후보마다 **새 로컬 workerd 인스턴스**를 만든다. 5예제×800/720을 사용하고 회차별 순서를 뒤집거나 후보 순서를 회전한다. 각 인스턴스에서 첫 조립1회, 후속4회, 반복20회를 실행하며 모든 결과의 전체 PNG 바이트를 비교한다.

- 세 실험 합계 **300개 새 인스턴스·7,500개 PNG**가 기준과 일치했다.
- 모듈 시작·글자 준비는 측정에서 제외한다. 첫 조립은 배포 시작 시간과 다르다.
- 경과 시간에는 호스트의 요청 전달·응답 읽기·바이트 비교가 들어간다. 프로파일러 비용도 있다.
- CPU 프로파일은100µs 간격의 비유휴 표본이다. 표본 수를 실제 CPU ms나 원격 개선율로 환산하지 않는다.
- 세 실험은 별도 실행이다. 서로 다른 실험의 시간·표본을 한 비교 집단으로 합치지 않는다. 메모리 상한과 원격 이벤트 누락을 해결한 시험도 아니다.

## 단계별 결과

### 1. 묶음 쓰기·구간 복사 비교

후보당20개 새 인스턴스, 총60개·PNG1,500개. [원자료](evidence/AI_PNG_BLIT_LOCAL_2026-10-03.json)

| 후보   | 첫 경과 시간 중앙값 | 반복 경과 시간 평균 |
| ------ | ------------------: | ------------------: |
| scalar |             13.23ms |              4.24ms |
| packed |             14.34ms |              4.22ms |
| spans  |             15.17ms |              4.56ms |

픽셀을 묶는 두 후보는 첫 프로파일 표본이 줄었지만 경과 시간은 길어졌다. 원인을 구분하기 위해 계산 방식이 같은 함수 분리 대조군을 추가했다.

### 2. 함수 분리 효과 대조

후보당40개 새 인스턴스, 총120개·PNG3,000개. [원자료](evidence/AI_PNG_BLIT_ISOLATION_LOCAL_2026-10-03.json)

| 후보      | 첫 경과 시간 중앙값 | 반복 경과 시간 평균 | 첫 비유휴 표본 합계 |
| --------- | ------------------: | ------------------: | ------------------: |
| scalar    |             13.46ms |              4.28ms |               1,110 |
| extracted |             13.38ms |              4.26ms |                 610 |
| packed    |             14.70ms |              4.25ms |                 726 |

단순 함수 분리만으로 표본 감소가 재현됐다. 이 실험의 중앙값 차이는0.08ms로 작으며 뚜렷한 경과 시간 개선으로 주장하지 않는다. V8의 함수 실행·최적화가 영향을 줬을 가능성은 **추론**이며 JIT 추적으로 확정한 원인은 아니다. 복잡한 4픽셀 계산보다 함수 분리를 선택했다.

### 3. native CRC 추가 대조

후보당40개 새 인스턴스, 총120개·PNG3,000개. [원자료](evidence/AI_PNG_BLIT_CRC_LOCAL_2026-10-03.json)

| 후보      | 첫 경과 시간 범위 | 첫 중앙값 | 첫 평균 | 반복 평균 | 첫 / 반복 비유휴 표본 |
| --------- | ----------------: | --------: | ------: | --------: | --------------------: |
| scalar    |     10.35~23.28ms |   13.82ms | 14.10ms |    4.30ms |         1,181 / 3,974 |
| extracted |     10.10~16.50ms |   13.32ms | 13.21ms |    4.26ms |           603 / 3,823 |
| native    |      9.66~16.02ms |   12.74ms | 12.62ms |    4.29ms |           562 / 3,123 |

함수 분리와 native CRC를 합친 후보의 첫 중앙값은 기존보다 **1.08ms 낮았다**. CRC만의 차이는 extracted→native의 **0.58ms**다. 반복 평균은 extracted보다 소폭 길며 기존과도 거의 같다. 표본 감소를 반복 경과 시간 단축으로 대신 보고하지 않는다. 각 후보의 첫 표본은40회, 반복 표본은800회에서 모았으므로 첫/반복 원시 합계도 직접 비교하지 않는다.

## 검증과 재현

관련 Vitest **3파일38개 통과**(10:21:33 KST 시작,55.40초):

- 3종 painter의 투명·겹침·7색·unaligned view·다양한 폭, packed의 알파 조합 전수 대조.
- 1080/800/720·6카드에서 기존PNG와 세 painter 및 native 조합의 전체 바이트 일치.
- 정상 PNG와19종 오류를 기본/native CRC 양쪽으로 검증. 잘못된 업로드의 KV·저장량·업로드 횟수 불변.

`npm run build`(타입·웹·제품 두 Worker dry-run), `npm run check:free`, 새 시험 Worker dry-run이 통과했다. 시험 번들은3,878.89KiB / gzip1,568.35KiB이며 정적 파일12,584개를 확인했다. dry-run은 배포가 아니다. 전체 Vitest/E2E와 실제 AI·카카오 연동은 이번에 실행하지 않았다.

저장소 루트에서 실행한다. 로컬 atlas 자료가 없으면 [기존 자산 준비 절차](AI_CARD_AUTOMATION_OPTIMIZATION.md#재현-명령)를 먼저 따른다. 비교 명령은 결과 파일을 같은 이름으로 다시 쓰므로 기존 증거를 보존한 별도 checkout에서 재현한다.

```powershell
npm test -- tests/automation-blit.test.ts tests/automation-optimized.test.ts tests/png.test.ts
npm run build
npm run check:free
npx wrangler deploy --config experiments/automation-png/wrangler.atlas-blit.jsonc --dry-run
node experiments/automation-png/research-blit-workerd.mjs
node experiments/automation-png/research-blit-workerd.mjs --isolate-loop
node experiments/automation-png/research-blit-workerd.mjs --native-crc
```

## 남은 조건

현재 계정 상태는 이 로컬 단계에서 다시 조회하지 않았다. 마지막 실제 확인은 직전 시험의 Workers Free·US$0이며, 새 원격 시험 전 재확인이 필요하다. 유료 의존성이나 원격 자원은 추가하지 않았다. 제품의 무료 구성 검사 통과가 이번 후보의 실제 무료 실행을 보증하지 않는다.

다음 미완료 단계는 선택한 후보를 동일 조건의 제한된 임시 시험에서 비교하고 **첫 조립·준비·수집 각각의 실제 CPU 및 로그 확보율**을 확인하는 것이다. 준비/수집은 이번 수정의 개선 대상이 아니므로 기존 초과 문제도 따로 남는다. 입력·PNG 검증을 줄이거나 유료 서비스로 우회하지 않는다. 무료 실행 선행 조건이 해결되기 전에는 전체 자동화를 완료·활성화한 것으로 표시하지 않는다.

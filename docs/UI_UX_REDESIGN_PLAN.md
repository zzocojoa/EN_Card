# 영어 카드 UI·UX 개편 계획

작성일: 2026-10-02 (Asia/Seoul)

상태: 승인 범위의 UI 구현·리뷰 보완·로컬 검증 완료 / 실제 아이폰·운영 배포는 별도

작업 브랜치: `codex/ui-ux-refresh` — `codex/development`의 `29c758d`에서 생성.

적용 스킬: `frontend-design` (`C:/Users/user/.codex/skills/open-design-frontend/SKILL.md`)

사용자 선택: 차분한 학습 작업실, PC 제작·아이폰 확인, 기존 5개 기능 화면 유지·동선 개선, 요약 홈 추가, 전체 화면 스타일 개편.

## 1. 확인 결과와 목표

**‘차분한 학습 작업실’ 디자인으로, PC에서는 카드 제작을 편하게 하고 아이폰에서는 예약과 발송 상태를 빠르게 확인하도록 개편합니다.** 기존 5개 기능 화면은 유지하고 요약 홈을 추가합니다.

조사 당시 `codex/development`의 작업 트리는 깨끗했습니다. 계획 저장 후 사용자 승인을 받아 같은 브랜치에서 구현했습니다. 세부 변경과 검증 범위는 [리뷰 기록](UI_UX_REVIEW.md)과 [검증 기록](VERIFICATION.md)의 UI 개편 항목을 따릅니다.

코드와 모의 데이터 화면을 확인했습니다. 주요 개선점은 다음과 같습니다.

- 아이폰 크기에서 메뉴 글씨가 9px, 입력 글씨가 13px로 작습니다.
- 예약 목록이 긴 작성 폼 아래에 있어 기존 예약을 확인하려면 많이 내려야 합니다.
- 카드 저장 후 다음 행동인 예약으로 바로 이어지는 안내가 부족합니다.
- 페이지가 URL에 반영되지 않아 새로고침과 브라우저 뒤로 가기가 화면 이동과 연결되지 않습니다.
- 발송 기록은 날짜·오류 중심이어서 어떤 카드를 보냈는지 식별하기 어렵습니다.

## 2. 페이지별 개편

| **요약 홈 — 신규** | 없음                           | 다음 예약, 카카오 연결, 확인할 발송 결과, 준비된 카드 수 표시. ‘카드 만들기’와 ‘예약 확인’ 제공                                    |

공개 `/images/…`와 `/original/…`는 현재 PNG를 직접 반환하는 경로이며 별도 앱 페이지가 아닙니다. 기존 원본 링크와 이미지 접근 방식은 유지합니다.

## 3. 디자인과 조작 기준

- **색상:** 밝은 회색 작업 배경, 흰색 콘텐츠 영역, 먹색 본문, 파란색 주요 행동. 오류·주의·성공은 색상과 문구를 함께 사용합니다.
- **글자:** 기존 로컬 Noto Sans KR을 유지합니다. 본문·입력은 16px, 메뉴·버튼은 14px 이상, 보조 정보는 12px 이상으로 정리합니다.
- **레이아웃:** 8px 간격 체계, 절제된 테두리와 그림자를 사용합니다. 반복되는 버튼·입력·상태 배지·알림·대화상자의 모양과 상태를 통일합니다.
- **PC:** 왼쪽 메뉴에 홈과 기존 5개 화면을 표시합니다. 카드 편집은 2열, 예약·기록은 비교하기 쉬운 목록 중심으로 구성합니다.
- **아이폰:** 하단 메뉴는 ‘홈·보관함·예약·기록·더보기’로 구성합니다. 더보기에는 카드 만들기와 설정을 제공하고, 홈·보관함에서도 카드 만들기로 바로 이동합니다.
- **모바일 편집:** 입력을 먼저 보여주고 미리보기는 펼쳐 확인합니다. 최소 44px 터치 영역, 하단 안전 영역, 키보드가 열린 상태의 스크롤과 저장 버튼 접근성을 확보합니다.
- **피드백:** 버튼에 작업별 진행 상태를 표시하고 입력 오류는 해당 필드에 연결합니다. 빈 화면에는 다음 행동을, 조회 실패에는 다시 시도를 제공합니다.
- **접근성:** 키보드 이동, 현재 메뉴 표시, 명확한 포커스, 대화상자 포커스 복귀, 일반 텍스트 대비 4.5:1을 확인합니다.

내보내는 카드는 기존 **1080×1080, 흰 배경·검정 영문·파란 뜻·회색 설명**과 두 템플릿을 유지합니다.

## 4. 구현 방식과 순서

1. 현재 HEAD에서 **`codex/ui-ux-refresh`** 브랜치를 생성합니다. 기존 사용자 변경이 생겼다면 먼저 보존합니다. **문서 저장 시 브랜치 생성 완료.**
2. 디자인 토큰과 공통 컴포넌트를 정리하고, 큰 앱 컴포넌트를 화면별로 분리합니다. 편집 중 입력은 화면 이동 후에도 메모리에서 유지합니다.
3. 주요 화면에 `#/home`, `#/editor`, `#/library`, `#/schedules`, `#/history`, `#/settings` 주소를 부여합니다. 로그인 후 기본 화면은 홈이며, 새로고침·뒤로 가기·앞으로 가기를 지원합니다.
4. 요약 홈과 카드 제작→예약 동선을 구현합니다. 저장·검토가 실제로 완료된 이미지로만 예약을 시작하고, 기존 예약 편집과 새 예약 작성을 구분합니다.
5. 보관함·발송 기록·설정과 모바일 화면을 개편하고, 진행·검증 문서에 결과를 기록합니다.

**API·타입 변경은 화면에 필요한 조회 기능으로 제한합니다.**

- `GET /api/state`에 홈용 요약을 추가합니다. 다음 활성 예약, 준비 카드 수, 확인 필요 건수는 전체 DB 기준으로 계산합니다.
- 카드 목록 API에 표현·뜻 검색과 상태·템플릿 필터를, 발송 목록 API에 확인 필요 필터를 추가합니다. 기존 커서 페이지네이션을 유지하며 필터 변경 시 목록과 커서를 초기화합니다.
- 발송 요약 타입에 저장된 발송 payload의 카드 제목과 예약 이름을 추가합니다. 이후 카드 수정 때문에 과거 발송 제목이 달라지지 않게 합니다.
- 검색·요약을 위해 전체 데이터를 브라우저로 내려받거나 상시 polling하지 않습니다. 진입·수동 새로고침·작업 완료 시 갱신합니다.
- 예약 실행, OAuth, 재시도, 결과 불명 처리 규칙과 DB 구조는 유지합니다. 취소·연결 해제·삭제에는 영향이 명확한 확인창을 제공합니다.

## 5. 검증과 완료 기준

- **핵심 흐름:** 카드 작성 → 미리보기 → 검토·저장 → 해당 카드 예약 → 홈에서 예약 확인을 연결해서 검증합니다.
- **조회 정확성:** 100개를 넘는 카드 검색, 첫 페이지 밖의 결과 불명, 필터 변경·더 불러오기에서도 누락·중복·잘못된 집계가 없는지 확인합니다.
- **상태·복구:** 로딩, 빈 데이터, 세션 만료, 저장 실패, 재연결 필요, 일시정지, 부분 복구, 결과 불명 처리와 기존 경합 보호를 회귀 검증합니다.
- **반응형:** PC 1440px, 태블릿 768px, 아이폰 폭 375·390·430px에서 확인합니다. 홈의 다음 예약과 조치 필요 안내는 아이폰 첫 화면에서 파악할 수 있게 합니다.
- **브라우저:** Chromium과 WebKit으로 검증합니다. 조사 당시 WebKit은 미설치이므로 실행 단계에서 테스트 브라우저를 준비합니다. 실제 아이폰 Safari의 키보드·날짜 입력·PNG 다운로드 확인은 자동화 결과와 별도로 기록합니다.
- **실행 명령:** `npm run test`, `npm run test:e2e`, `npm run build`, `npm run check:free`. 기존 핵심 테스트를 유지하면서 변경된 사용자 흐름에 맞게 갱신합니다.

이번 조사에서는 **모의 데이터 화면 점검과 `check:free`가 통과**했습니다. 실제 아이폰·운영 계정 상태를 새로 검증한 것은 아닙니다. 신규 유료 서비스나 UI 라이브러리 없이 기존 React·CSS·로컬 폰트를 사용하며, 구현 완료 범위는 로컬 검증까지입니다. 운영 배포와 실제 카카오 발송은 별도로 진행합니다.

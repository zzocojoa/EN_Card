## 1. 비개발자를 위한 설명

**한 번 설정하고 ‘자동화 시작’을 누르면, 매일 AI가 카드 한 장을 만들고 다른 AI의 검토를 거쳐 카카오 발송을 예약합니다.** PC와 브라우저를 꺼도 클라우드에서 진행하도록 구현합니다.

| 순서        | 사용자가 하는 일                         | 시스템이 하는 일                       |
| ----------- | ---------------------------------------- | -------------------------------------- |
| 설정        | 주제·기준 표현, 난이도, 카드 종류를 선택 | 설정을 저장                            |
| 일정 지정   | 시작일과 매일 받을 시각을 지정           | 한국 시간으로 다음 제작·발송 시각 표시 |
| 자동화 시작 | 시작 버튼을 한 번 누름                   | 매일 카드 한 장 제작                   |
| 내용 검토   | 매번 확인할 필요 없음                    | 다른 AI가 뜻·문법·번역 등을 검토       |
| 이미지·예약 | 필요하면 결과를 확인                     | 통과한 내용을 PNG로 만들고 예약        |
| 수신        | 카카오 ‘나와의 채팅’에서 확인            | 기존 예약 발송 기능으로 전달           |

예를 들어 **‘여행 영어 / 초급 / 매일 오전 8시’**로 설정하면, 오전 7시부터 제작하고 검토와 이미지 저장을 완료한 카드만 오전 8시 발송 대상으로 등록합니다.

PNG는 하루단어에 보관하며, 필요할 때 휴대전화나 PC로 다운로드할 수 있습니다.

**기본값**

- 하루 한 장, 동시에 실행하는 자동화는 한 개.
- 표현형 카드를 기본으로 하고 비교형도 선택 가능.
- 입력한 주제·기준 표현을 중심으로 매일 다른 관련 표현을 생성.
- 시작일과 발송 시각은 필수이며, 종료일은 선택.
- 첫 발송까지 한 시간의 준비 시간이 없으면 다음 가능한 날짜부터 시작하고 화면에 안내.

## 2. AI 제작·검토 규칙

### 모델 역할

| 상황                  | 초안 작성                    | 독립 검토                    |
| --------------------- | ---------------------------- | ---------------------------- |
| 기본 흐름             | Google Gemini 3.1 Flash-Lite | Groq GPT-OSS 120B            |
| Gemini 초안 작성 실패 | Groq GPT-OSS 120B            | Google Gemini 3.1 Flash-Lite |

모델 식별자는 각각 `gemini-3.1-flash-lite`, `openai/gpt-oss-120b`를 사용합니다. 카드 필드를 정해진 형식으로 받는 구조화 출력 기능을 사용합니다. [Google 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite), [Groq 구조화 출력 문서](https://console.groq.com/docs/structured-outputs)

**두 모델이 모두 참여해야 예약할 수 있습니다.** Groq가 대신 작성했더라도 Gemini가 검토할 수 없으면 해당 카드를 예약하지 않습니다.

### 통과 조건과 실패 처리

- 검토 항목은 표현의 자연스러움, 한글 뜻, 예문 문법, 번역 일치, 선택한 난이도, 비교형 설명의 정확성입니다.
- 프로그램도 필수 항목·글자 수·기존 표현 중복·이미지에 들어가는 분량을 검사합니다.
- 문제가 발견되면 작성 모델이 **한 번 수정**하고, 다른 모델이 다시 검토합니다.
- 재검토에서도 실패하면 **그날은 건너뛰고 다음 날 계속**합니다.
- 일시적인 통신 장애는 해당 단계에서 최초 포함 최대 세 번까지 제한적으로 재시도합니다. 발송 5분 전까지 준비되지 않으면 그날 작업을 종료합니다.
- 인증 오류·무료 이용 조건 불충족·저장 공간 부족은 자동화를 일시정지하고 필요한 조치를 표시합니다.
- 생성 결과에는 **‘AI 교차 검토 완료’**를 표시합니다. 사람이 검토했다고 기록하지 않으며, AI 검토가 정확성을 보장한다고 안내하지 않습니다.
- 한글식 발음은 초기 자동 생성에서 생략합니다.

## 3. 가장 먼저 확인할 조건: 무료 무인 PNG 생성

현재 PNG 생성 코드는 브라우저에서 실행됩니다. 무인 제작을 위해서는 서버에서 한글 카드 이미지를 만드는 기능이 추가로 필요합니다.

Cloudflare 일반 Worker Free는 HTTP 요청과 정기 실행 모두 CPU 시간이 **10ms**로 제한됩니다. 별도의 SQLite DO는 Free에서도 기본 CPU **30초**를 사용하므로 이미지 제작·검증·저장을 DO에 배치합니다. 격리 시험의20장은 통과했고, 제품의 제작·검토·예약까지 연결한 전체 무인 경로는 별도 성능 검증이 필요합니다. [일반 Worker 한도](https://developers.cloudflare.com/workers/platform/limits/), [DO 한도](https://developers.cloudflare.com/durable-objects/platform/limits/)

첫 구현 단계는 다음 검증으로 한정합니다.

1. 기존 카드 배치 규칙과 한글 폰트를 이용해 SVG를 만들고, `resvg`의 WebAssembly 버전으로 1080×1080 PNG를 생성합니다.
2. 표현형·비교형, 긴 한영 문장, 첫 실행·반복 실행에서 글자 깨짐·잘림·파일 크기·CPU·메모리를 확인합니다.
3. 독립적인 이미지 변환뿐 아니라 실제 예약 처리와 연결한 경로에서도 무료 한도를 확인합니다.
4. Google·Groq 계정의 무료 이용 조건과 기존 하루단어 AI 기능이 함께 사용하는 호출 한도를 확인합니다.

**통과하면 다음 구현 단계로 진행합니다. 최적화 후에도 무료 한도를 넘으면 무인 기능 활성화를 보류하고 측정 결과와 대안을 보고합니다.** 유료 상품으로 자동 전환하지 않습니다.

## 4. 구현할 화면과 내부 기능

### 사용자 화면

현재 카드 화면의 디자인을 유지하면서 **‘AI 자동 제작’** 영역을 추가합니다.

- 설정: 주제·기준 표현, 난이도, 표현형·비교형, 시작일·종료일, 매일 발송 시각.
- 조작: 설정 저장, 자동화 시작, 일시정지, 재개.
- 상태: 다음 제작·발송 시각과 오늘의 진행 단계.
- 기록: 생성된 카드, 작성·검토 모델, 검토 결과, 예약·발송 결과, 건너뛴 이유.
- 결과: PNG 미리보기·다운로드와 기존 카드 편집으로 이동.

일시정지는 해당 자동화의 제작과 아직 발송을 시작하지 않은 예약을 중단합니다. 설정을 변경하면 새 설정으로 향후 작업을 다시 계산합니다. 이미 카카오에 접수된 메시지는 회수할 수 없습니다.

### 서버·데이터 연결

- 기존 클라우드 정기 실행 하나를 유지하고, **제작 → 검토 → 이미지 저장 → 예약**을 단계별 작업으로 추가합니다.
- AI·이미지 처리용 비공개 Worker를 두고 단계 결과를 D1에 저장합니다. 서버가 중단되어도 완료한 단계를 확인하고 이어서 처리합니다.
- 자동화 설정, 날짜별 작업, 검토 결과를 저장하는 테이블을 추가합니다. 같은 자동화·날짜의 작업과 예약이 중복 생성되지 않도록 제한합니다.
- AI 검토는 카드의 특정 수정본에 연결합니다. 내용이 바뀌면 이전 검토 승인을 사용할 수 없습니다.
- 통과한 PNG는 기존 KV 저장 절차를 사용합니다. 이미지 저장 후 최소 2분의 여유를 확보하고, 해당 날짜의 한 장짜리 예약을 기존 발송 엔진에 등록합니다.
- 지난 날짜의 실패 작업을 몰아서 제작·발송하지 않습니다. 기존 발송 결과가 불명확하면 기존 중복 방지 규칙에 따라 후속 발송을 막습니다.
- AI가 만든 내용을 임의 코드·HTML로 실행하지 않고 카드 데이터로만 처리합니다.

### API·접근 권한

하루단어의 기존 본인 인증과 카드 연결 경로에 다음 인터페이스를 추가합니다.

| 인터페이스                               | 용도                        |
| ---------------------------------------- | --------------------------- |
| `GET/PUT /api/card-studio/automation`    | 설정·현재 상태 조회 및 저장 |
| `POST /api/card-studio/automation/start` | 시작·재개                   |
| `POST /api/card-studio/automation/pause` | 일시정지                    |
| `GET /api/card-studio/automation/runs`   | 날짜별 실행 결과 조회       |

본인만 호출할 수 있도록 기존 소유자 확인·요청 출처 검증을 적용합니다. API 키는 서버 Secret에 보관하고, 무인 실행에 브라우저 로그인 쿠키를 사용하지 않습니다.

기존 학습 피드백 API와 분리된 카드 생성·검토 계약을 추가합니다. AI 공급사에는 해당 카드 작업에 필요한 내용만 전달합니다.

## 5. 구현 순서와 완료 기준

| 단계              | 작업                                 | 완료 기준                               |
| ----------------- | ------------------------------------ | --------------------------------------- |
| 1. 무료 실행 검증 | 서버 PNG와 실제 계정 조건 확인       | 무료 한도 내 실행 근거 확보             |
| 2. AI 제작·검토   | 두 모델 연결, 수정·재검토, 오류 처리 | 통과한 카드만 다음 단계로 이동          |
| 3. 무인 실행      | 날짜별 작업·PNG 저장·예약 연결       | 화면을 닫아도 처리되고 중복 예약 없음   |
| 4. 화면 연결      | 설정·시작·일시정지·결과 표시         | 모바일에서도 상태와 실패 이유 이해 가능 |
| 5. 통합 검증      | 기존 기능 회귀 검사와 실제 기기 확인 | 자동 제작부터 실제 수신까지 확인        |

**검증 항목**

- 정상 생성, Gemini 실패 시 역할 전환, 한 모델만 사용 가능한 경우.
- 잘못된 응답, 부정확한 번역, 중복 표현, 수정 후 재검토 실패.
- 한글·영문 줄바꿈, 비교형, 긴 내용, PNG 용량 제한.
- 정기 실행 중복·서버 중단·설정 변경·일시정지 경합.
- 한국 시간 날짜 경계, 준비 시간 부족, 무료 한도·인증·저장 실패.
- 기존 수동 카드 제작·PNG 다운로드·카카오 예약 기능.
- PC와 브라우저를 종료한 상태의 자동 제작 및 승인된 범위의 실제 카카오 수신.

구현은 관련 저장소의 최신 변경을 보존한 `codex/` 브랜치에서 진행합니다. 자동화는 기본 비활성 상태로 배포하며, 기능 검증 후 사용자가 시작 버튼으로 활성화합니다.

단계별 구현 결과는 [진행 기록](PROGRESS.md)에 남기고, 실제 검증 근거는 [검증 기록](VERIFICATION.md)에 구분하여 기록합니다. 구현 착수 시 기존의 ‘AI 미사용·사람 검토 필수’ 설명을 새 동작에 맞게 갱신합니다.

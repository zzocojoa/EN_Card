# 하루 한 표현

직접 고른 영어를 1080×1080 카드로 만들고 본인 카카오톡의 **나와의 채팅**으로 예약 발송하는 개인용 웹앱입니다. 한국어 화면, 표현형·비교형 템플릿, JSON/PNG 백업과 복원, 한국 시간 예약, 발송 기록을 제공합니다.

기본 설정은 **dry_run**입니다. 2026-09-30 본인 카드의 실제 API 접수·휴대전화 이미지·원본 링크와 CPU Cron 5ms·준비 5ms·발송 10ms를 확인했습니다. 2026-10-01 08:02 KST 승인 후 R7/R8을 기존 두 Worker에 live로 배포했습니다. 09:00 예약은 09:01:24에 자연 만료 토큰의 정상 갱신과 1회 API 접수를 확인했습니다. 당시 CPU는 Cron 14ms·준비 4ms·발송 10ms로 갱신 포함 Cron이 10ms 목표를 넘어 CPU 보완을 진행했습니다. 09:10 예약은 09:11:07에 1회 접수됐으며 사용자가 PC·Chrome·Codex 종료 상태에서 09:11 휴대전화 이미지 수신과 원본 링크 정상 열림을 확인했습니다. 활성 예약은 0개입니다. 최신 결과는 [검증 기록](docs/VERIFICATION.md)을 따릅니다.

정상 갱신과 발송을 다른 Cron 실행으로 분리하는 CPU 보완 `8638e2a`는 전체 로컬 251개·Chromium 19개·두 Worker 빌드·무료 구성 검사를 통과했으며, 사용자 승인 후 2026-10-01 10:32~10:33 KST에 기존 두 Worker에 배포했습니다. 후속 조기 갱신 한 장 시험에서 갱신 Cron/준비/정리 **6/2/2ms**, 다음 발송 Cron/준비/전송 **2/1/3ms**를 확인했습니다. 기존 두 Worker·DB/KV·Secrets를 사용하며 새 자원이나 유료 구성을 추가하지 않습니다.

후속 승인된 **10:45 유효 토큰 한 장 시험**은 10:45:57에 실제 API 접수를 확인했고 사용자 사진에서도 10:45 이미지 수신을 확인했습니다. CPU Cron/준비/발송 **4/2/7ms**로 모두 10ms 이내였습니다. 이 수치는 유효 토큰 경로의 측정이며 정상 갱신 경로의 CPU로 사용하지 않습니다.

사용자의 **조기 갱신 시험 변경 승인**으로 기존 16:42 예약을 **11:30 KST 같은 본인 카드 한 장**으로 앞당겼습니다. 앱 저장 액세스 만료 시각만 조건부로 과거로 조정해 실제 카카오 갱신을 유도했고, 인증 version 7→8·갱신 단계 발송 시도 0·다음 Cron에서 **11:31:52 실제 API 접수 1회**를 확인했습니다. 사용자가 휴대전화 수신·이미지·원본 정상도 확인했습니다. 자연 만료 시험과 구분하며 키·토큰 원문·refresh 만료를 직접 바꾸지 않았습니다. 11:30 시험 종료 당시 활성 예약 0·오늘 시도 4회였으며 수집기와 후속 점검은 종료했습니다. 이 한 장 실측을 모든 부하의 CPU 보장으로 확대하지 않습니다.

현재 운영 제품 소스는 `b24c2df`(배포 기준 HEAD `bf1726d`)·D1 0012이며, 사용자 승인으로 2026-10-01 18:55 KST에 기존 두 Worker에 반영했습니다. R12/R13/R14·복구 오류 안내·구성 검사·안내 대비 보완은 전체 299개·Chromium 19개 검증본입니다. 백업·쓰기 중단·12개 이력·FK 오류 0과 기존 데이터 보존을 확인했습니다. 최신 자연 만료 갱신 CPU **6/3/2ms**·다음 실행 발송 **2/1/8ms**로 각 호출 10ms 이내를 확인했고, 19:04:36 API 접수 1회와 사용자 휴대전화 수신·이미지·원본도 확인했습니다. 활성 예약 0·오늘 시도 5/20이며 실제 다량 CPU는 미검증입니다. 상세 결과는 [검증 기록](docs/VERIFICATION.md)을 따릅니다. 이전 실측을 새 코드의 CPU로 사용하지 않습니다. 변경 근거는 [배포 후 리뷰](docs/REVIEW_2026-10-01_POST_DEPLOY.md)를 따릅니다.

## 로컬 시작

Node.js 22.12 이상을 사용합니다. 개발 worktree에서 실행하세요.

```sh
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:8787 을 열고 **로컬 작업실 열기**를 누릅니다. 로컬 설정의 공개 테스트 값은 실제 인증 정보가 아닙니다. 실제 카카오 자격 증명 없이 시작할 수 있습니다.

1. 카드 만들기에서 내용을 입력하거나 보관함에서 JSON/예제 12개를 가져옵니다.
2. 미리보기와 내용을 확인하고 검토 체크 후 PNG를 저장합니다.
3. 발송 예약에서 검토 완료된 카드와 2분 이후의 시각을 선택합니다.
4. 예약 발송 미리검증을 실행하고 발송 기록을 확인합니다. 이 동작은 카드 목록을 소비하지 않습니다.

목록은 100개씩 불러오며 **더 불러오기**로 이전 자료에 접근합니다. JSON 백업도 파일당 최대 100개입니다. **다음 JSON 백업** 버튼이 없어질 때까지 모든 파일을 보관하고, 복원할 때 각 파일을 한 번씩 가져옵니다.

운영 예약은 Worker의 Cron Trigger가 실행합니다. 준비·발송은 공개 URL이 없는 `en-card-delivery`에 Service Binding으로 연결합니다. 로컬 개발 서버는 테스트용이며 PC를 끄면 중단됩니다. 실제 클라우드 실행 조건과 두 Worker의 배포 순서는 [설정·배포 절차](docs/SETUP.md)에 있습니다.

## 검증

```sh
npm run build
npm run check:free
npm test
npx playwright install chromium
npm run test:e2e
```

`build`에는 타입 검사·Vite 빌드·주 Worker와 비공개 발송 Worker의 배포 dry-run이 모두 포함됩니다. 별도 검사는 `npm run deploy:dry-run`, `npm run deploy:delivery:dry-run`입니다. 두 명령은 원격에 배포하지 않습니다. E2E는 8787 포트와 별도 `.wrangler/e2e-*` 저장소를 사용하므로 개발 서버를 종료한 뒤 실행합니다.

## 운영 및 비용 조건

React/Vite, 브라우저 Canvas, Workers Free + Static Assets, D1 Free, KV Free, 카카오 공식 나에게 보내기 API만 사용합니다. 유료 AI API·R2·Cloudflare Images·유료 메시지·별도 도메인 의존성이 없습니다. 무료 한도 초과 시 멈추며 유료 상품으로 전환하지 않습니다. **실제 계정의 Free 플랜 확인은 별도로 필요합니다.** 설정 검사는 계정 청구 차단 기능이 아닙니다.

무료 나에게 보내기는 **푸시 알림·알림음이 없습니다**. 한 카드당 이미지 피드 메시지 한 개로 발송하며 원본 보기 링크를 제공합니다. 일반 사진 첨부나 여러 사진의 묶음 전송과 다릅니다. 인증 만료·제공사 장애·무료 한도로 늦어지거나 멈출 수 있으며 정시 도착·무중단·영구 무료를 보장하지 않습니다.

이미지 URL을 아는 사람은 해당 카드를 볼 수 있습니다. 토큰·예약·카드 목록은 공개하지 않습니다. 발송 결과가 불명확하면 자동 재발송하지 않고 사용자 확인을 기다립니다.
